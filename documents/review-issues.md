# Code Review Issues - Property NI Multi-Tenant Portal

This document consolidates findings from multiple code reviews of the Property NI Multi-Tenant Portal. Issues are categorized by severity and include recommendations for remediation.

| Severity | File / Component | Issue Description | Recommendation |
|:---|:---|:---|:---|
| **Critical** | `prisma/seed.ts` | **Hardcoded Default Password & `.env` Mutation**: The seed script falls back to a hardcoded default password if `ADMIN_PASSWORD` is unset. It also writes `PLATFORM_ORG_ID` directly to the `.env` file at runtime, which is fragile and dangerous. | Fail the seed with an error if `ADMIN_PASSWORD` is not set. Store platform config in a dedicated DB table or Prisma metadata column instead of mutating `.env`. |
| **Critical** | `app/api/admin/organizations/route.ts` | **Email-Based Auth Bypass**: Admin routes have a `try/catch` around DB authorization that falls back to checking if the user's email matches a hardcoded default. If the DB is down, this bypasses all authorization checks. | Remove the email fallback entirely or log it at error level and reject access. The DB should be required for authorization decisions. |
| **Critical** | `.env` (Root) | **Committed Secrets**: The root `.env` file is committed to the repository, likely containing `DATABASE_URL`, `BETTER_AUTH_SECRET`, and PII keys. | Add `.env` to `.gitignore` immediately and rotate any secrets that may have been exposed. |
| **High** | `services/organization-service.ts` | **Error Swallowing & Atomicity Gaps**: The `createOrganization` method catches errors but swallows them, hiding failures. Additionally, creating an org and its admin user/member lacks `prisma.$transaction`, risking orphaned states if bootstrap fails mid-way. | Wrap the operation in a Prisma transaction to guarantee atomicity. Re-throw errors or log them appropriately instead of silently catching. |
| **High** | `lib/global-db.ts` | **Tenant Isolation Bypass**: The global DB client explicitly bypasses tenant isolation. There is no runtime enforcement preventing its misuse outside of super-admin routes, despite comments warning against it. | Add a runtime check that throws if `globalDb` is used outside of a super-admin context, or rename it to make the danger unmistakable. |
| **High** | `lib/authz-route.ts` | **Platform Org Protection Skipped**: The `requireNonPlatformOrgRoute` function completely skips enforcement if the request doesn't include an `orgId`. An attacker could craft requests without this header to bypass checks. | Require org context for all mutations or validate the target resource's actual org ID against the platform org. |
| **High** | `/login` (Auth) | **No Rate Limiting**: The login endpoint lacks rate limiting, brute-force protection, or account lockout configuration. | Add rate limiting to the auth endpoint (e.g., via `rateLimit` option in Better Auth or a middleware wrapper). |
| **High** | `lib/permissions/resolver.ts` | **Redis KEYS Blocking**: The `invalidateUserCache` function uses `redis.keys(pattern)`, which is an O(N) command that blocks the Redis event loop during cache invalidation, causing latency spikes under load. | Replace `KEYS` with `SCAN` to safely iterate over keys without blocking Redis, especially during high-traffic permission updates. |
| **High** | `lib/permissions/resolver.ts` | **Silent Error Swallowing**: The permission resolution function has a `catch` block that returns an empty list on error. While "fail-closed," it makes debugging difficult and could lead to fail-open scenarios if intermediate layers don't check. | Log the error at least: `logger.warn({ err, msg: 'Permission resolution failed' })`. |
| **Medium** | `lib/tenant-db.ts` | **Loose Type Safety for Tenant Models**: `TENANT_SCOPED_MODELS` is defined as a loose string array. If a model name changes in `schema.prisma`, the extension silently fails to scope it, relying solely on RLS as a fallback. | Use `keyof PrismaClient` or a stricter type mapping to ensure the array stays in sync with the actual Prisma schema models at compile time. |
| **Medium** | `app/api/health/route.ts` | **Fragile Connection Reset Logic**: The route contains manual logic to reset the DB connection if it's closed. This is brittle, can cause race conditions, and drops active requests during recovery. | Implement a robust connection pool manager or use Prisma's built-in middleware to handle connection state gracefully instead of manual reset logic. |
| **Medium** | `lib/constants.ts` vs `org-bootstrap.ts` | **Duplicate Role-Permission Definitions**: Default role permissions are defined in two places (`constants.ts` and `org-bootstrap.ts`). They can drift apart, causing bootstrapped orgs to get different permissions than documented. | Enforce a single source of truth: import `DEFAULT_ROLE_PERMISSIONS` directly from constants in the bootstrap function. |
| **Medium** | `lib/system-logs.ts` | **In-Memory Logs Lost on Restart**: System health logs are stored in a module-level array. All logs are lost on server restart, making incident diagnosis impossible. | Persist system logs to the `SystemLog` database model or an external logging service. |
| **Medium** | `lib/audit.ts` | **Audit Events Not Persisted**: The `logAuditEvent` function only writes to structured logs. A TODO comment indicates DB persistence is planned but has been sitting indefinitely. | Implement actual persistence to the database or remove the stale TODO if it's no longer relevant. |
| **Medium** | `lib/notifications/email.ts` | **XSS in Email Template**: The `createEmailTemplate` function interpolates raw messages directly into HTML without escaping. If the message contains `<script>` tags, it could lead to XSS in email clients. | Escape HTML entities in the message before interpolation or use a proper templating library. |
| **Medium** | `middleware.ts` | **Missing Security Headers**: The CSP is well-configured, but other headers like `X-Content-Type-Options: nosniff` and `Referrer-Policy` are missing. | Add standard security headers to the middleware response. |
| **Medium** | `tests/setup.ts` | **Empty Test Setup**: The `beforeEach` and `afterEach` hooks are no-ops. There is no test database setup, transaction rollback, or fixture management. | Implement proper test fixtures and transaction rollbacks to ensure test isolation. |
| **Medium** | `lib/organization.ts` | **Misleading Role Hierarchy Logic**: The `hasOrganizationRole` function uses an inverted index comparison (`userIndex <= requiredIndex`) which is correct for hierarchy but misleadingly named. | Rename the function to reflect its actual behavior (e.g., `hasHigherOrEqualPrivilege`) or refactor the logic for clarity. |
| **Medium** | `lib/permissions/resolver.ts` | **Cache Key Collision Risk**: The cache key uses a colon separator (`userId:orgId`). If IDs contain colons (unlikely with CUIDs but not guaranteed), key parsing could break. | Use a more robust separator (e.g., `::` or JSON stringification) for cache keys. |
| **Medium** | Architecture / `lib/authz.ts` | **Super Admin Bypass & Caching Gap**: The `isSuperAdmin` check short-circuits authorization, meaning super admin permissions are never resolved or cached in Redis. While intentional, this causes confusion during debugging and performance profiling. | Document this bypass explicitly in `SECURITY.md`/`ARCHITECTURE.md`. Consider adding a debug flag or explicit logging to clarify why `resolvePermissions` isn't called for super admins. |
| **Low** | `hooks/usePermission.ts` | **Excessive `as any` Casts**: Six instances of `as any` are used to access custom session fields (`permissions`, `isSuperAdmin`), defeating TypeScript's type safety. | Define a proper session type that extends BetterAuth's session type with the custom fields. |
| **Low** | `middleware.ts` | **CSP Missing Directives**: The Content Security Policy doesn't include `worker-src` or `child-src`. Next.js uses these for various features, and missing them may cause production issues. | Add `'self'` to `worker-src` and `child-src` directives. |
| **Low** | `app/api/admin/audit-logs/route.ts` | **Stub Implementation**: The audit logs API returns empty data (`logs: []`). This is a TODO endpoint that should be implemented. | Implement actual data retrieval and pagination logic. |
| **Low** | `lib/env.ts` | **REDIS_URL Has a Default**: Redis is described as "optional" but has a default value (`redis://localhost:6379`). If Redis isn't running, the app will silently try to connect and fail gracefully. | Remove the default so missing Redis is caught early during startup (fail-fast). |
| **Low** | `app/api/admin/organizations/route.ts` | **Duplicated Super-Admin Check**: Both GET and POST handlers repeat the same session + super-admin check logic. | Refactor to use `requireSuperAdmin()` for consistency with other admin routes. |
| **Low** | `app/api/roles/route.ts` | **Missing Permission Check on GET**: Only a POST handler exists (for creating roles). There's no GET handler to list roles, implying the frontend uses a different endpoint. | Add appropriate role/permission validation to the GET endpoint if it's intended to be part of this route. |
| **Low** | API Routes (General) & `lib/permissions/resolver.ts` | **Leftover Debug Logs**: Several files contain `console.log` statements (e.g., in permission resolution and auth flows) that should not be in production code. | Replace `console.log` with the structured logger (`lib/logger.ts`) and ensure debug logs are only emitted in development environments. |
| **Low** | Components (General) | **Inline Styles**: The login page and admin pages use extensive inline style objects instead of Tailwind classes, making the code harder to maintain. | Refactor components to use Tailwind CSS classes for consistency with the rest of the codebase. |
| **Low** | `lib/organization.ts` | **Dead Code**: `getCurrentOrganization` returns null with a TODO comment. This is dead code that should either be implemented or removed to avoid confusion. | Implement the function or remove it if not needed. |
| **Low** | `lib/organization-context.tsx` | **Context Not Updated**: The `OrganizationProvider` has a TODO to "Update AsyncLocalStorage tenant context" when switching organizations, but it doesn't do anything. Switching orgs in the UI has no effect on API calls. | Implement the logic to update `AsyncLocalStorage` and session cookies when the organization is changed. |
| **Low** | `app/admin/organizations/[id]/page.tsx` | **Empty Data Tabs**: The roles and audit tabs render with hardcoded empty arrays (`roles={[]}`, `entries={[]}`), indicating incomplete tab implementations. | Connect these tabs to their respective API endpoints and data fetching logic. |
| **Low** | Prisma / DB Config | **Connection Pool Exhaustion Risk**: Wrapping org creation in transactions increases connection hold time. Under high concurrency, this can exhaust the PostgreSQL connection pool. | Tune Prisma's `maxConnection` and `minConnection` settings, or introduce `pgbouncer` in transaction mode to manage pool allocation efficiently. |
