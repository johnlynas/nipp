# effect ReDoS Audit Fix (GHSA-7589-6fvf-x4pw) — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Clear the 3 high-severity `effect <=3.22.0` ReDoS findings from `npm audit --audit-level=low` without downgrading Prisma (the naive `npm audit fix --force` path would install prisma@6.12.0 — a breaking downgrade of the deliberately-migrated Prisma 7 stack).

**Architecture:** The vulnerable tree is `prisma@7.10.1 → @prisma/config@7.10.1 → effect@3.20.0` (dev-only chain: prisma is a devDependency; no runtime code imports it — scripts only, e.g. `db:migrate`, `db:seed`). Upstream has published fixed `effect` 3.22.1–3.22.5, and there is **no newer stable Prisma** (registry: latest = `8.0.0-rc.35` pre-release; last stable = 7.10.1). The fix is a single `package.json` override pinning `effect` to the fixed patch line, a clean reinstall so the override lands in the lockfile, then gate on type-check/lint/build/tests + audit.

**Tech Stack:** npm overrides (already used in this repo for `postcss-selector-parser`, `minimatch`), Prisma 7.10.1, vitest gates.

## Assumptions / risks (up front)

1. **Override is a band-aid.** It forces effect 3.22.5 into a tree that pins 3.20.0. Prisma's config CLI uses effect internally; if it breaks, it surfaces in `prisma` CLI commands (migrate/validate/studio), not in the app runtime. Mitigation: Task 4 smoke-tests the prisma CLI directly.
2. **effect 3.x → 3.22.5 is a patch-line jump** (3.20.0 → 3.22.5), same major; low risk, but not zero. If the prisma CLI smoke test fails, fallback = accepted-risk row in SECURITY.md + tracked follow-up issue for the next Prisma stable that ships effect ≥3.22.1 (same pattern as the deepmerge-ts row at `SECURITY.md:715`).
3. **Do NOT run `npm audit fix --force`** — it downgrades prisma to 6.12.0, reverting the Prisma 7 migration.
